## 1. Overview & vision

Ask the Skipper lets a rider, mid-drive, hold a button, ask the Skipper a question out loud, and hear him answer in his own voice — grounded in the exact same facts the tour was built on, ducked over the narration, then drop them back into the tour where they left off. It is a **toy, driving-first** feature. The whole point is charm and trust: the guide you've been listening to turns and answers you, and when he doesn't know, he says so with a grin instead of making something up. Optimize for the builder and for charm, not for scale or latency.

**What success feels like in the car:** you're rolling past Emerald Bay, the Skipper finishes a line about Vikingsholm, you thumb the big button and say "who built that castle?" The tour dips, a soft bell, two seconds later the same voice comes back — "That'd be a woman named Lora Knight, folks, nineteen twenty-nine..." — and the narration swells back up. You never looked at the screen. You ask a follow-up he can't answer and he says "that one's not in my logbook, friend" and you laugh and trust him *more*, not less.

**North star (one paragraph):** A grounded, in-persona, voice-to-voice Q&A turn layered *around* the existing tour — push-to-talk in, the current stop's frozen Wikipedia fact-well as the only source of truth, Claude Sonnet 4.6 (`claude-sonnet-4-6` — the fast tier, NOT the Opus narration model) for the answer, the same Google "Algenib" voice for continuity, ducked over the tour, ~2–3s to first audio masked by a persona "let me check the logbook" filler. The grounding well already exists on `pois.facts.extract`; the persona already exists in `SKIPPER_SYSTEM_PROMPT`; the auth wall, the TTS call, and the Anthropic call already exist in the generator. This feature is mostly *wiring and re-framing* — its highest-leverage new artifact is the ASK system prompt, exactly as the narration prompt is for the tour.

## 2. The non-negotiable: grounding + the "not in my logbook" refusal

This is the cardinal invariant and it governs every other decision: **persona lives in delivery, never in facts.** "Make it charming" must never loosen "make it true." A live LLM answering open spoken questions will hallucinate unless it is boxed into the exact fact well the narration used, with a persona-true refusal as the only escape.

The load-bearing facts that make this enforceable:

- **The well already exists and is queryable.** For STORY stops, generation persists `pois.facts = { extract, title, url, pageId }` (`generate.ts:393-401`; column `schema.ts:105`, typed `PoiFacts` jsonb — note `PoiFacts` is `Record<string, unknown>`, so `facts.extract` is `unknown` and needs narrowing to `string` at the ask call site, §6.3 step 7). For stops generated by the deep-extract code path (`generate.ts:165-184`, mutation `s.facts = toFacts(text)` at `:181`), `extract` is the **deepened full-article Wikipedia text** (capped `DEEP_EXTRACT_CHARS=4000`, References/See-also trimmed) — byte-for-byte the same well that fed `buildFactSheet` at generation time. The deepening is best-effort and was added *after* the first tour generation: a tour generated before it (or whose deepen call failed) holds the ~600-char **lead** extract (`config.ts:84 EXTRACT_CHARS`). Grounding integrity is identical either way (same persisted string feeds narration and ask); only the *depth* differs, which matters for §12's "rich well" assertions — **verify the test tour's depth before relying on them (§12 step 0)**. No schema change is needed to *answer*.
- **Ground on `pois.facts.extract`, NOT on `poi_content.script`.** The script (`schema.ts:134`) is the persona-laden narration — a curation wrapped in jokes that drops most facts. Grounding on it loses facts and risks treating a joke as a fact.
- **Scenic/break stops have NO well.** They persist `facts: null` by construction (`generate.ts:393-401`). A question there has nothing to ground against and **must** hit the refusal path — the server never calls the LLM with an empty well.
- **Scope to ONE stop — the current/just-passed stop only [DECIDED 2026-06-07].** Fact wells are per-POI sentence sets with no cross-POI index. Pour two stops in and the model misattributes A's fact to B. Only the active stop's well enters a turn (neighbor *names* only, for deixis — never their facts). **Forward-looking questions ("what's coming up?") get a gentle persona deflection** ("we'll get there, friend") — never upcoming-stop facts; keeps grounding tight and avoids spoiling the tour's reveals.
- **Short multi-turn memory does NOT loosen grounding [DECIDED 2026-06-07].** A turn may carry the last ≤2 Q&A on the SAME stop so the skipper resolves "tell me more" / "what about her?" — but those prior turns are context for *reference resolution only*. Every claimed fact must still be in the CURRENT stop's well; an out-of-well follow-up still refuses. The conversation **resets when the active stop changes** (new well, fresh context). See §3.2 + the `history` field in §6.
- **Round-trip is exact by construction.** The ask path re-splits the persisted `extract` with the **same canonical `toFacts`** (`select.ts:84`) the generator used, so the bulleted fact array the model sees at ask-time is identical to the one `buildFactSheet` emitted (`toFacts` splits on `.!?`+whitespace; whatever abbreviation behavior it had at generation time it reproduces here — there is no second, divergent splitter). This is an explicit assumption, satisfied because the splitter is shared and the input string is the same persisted bytes.

**The refusal is a feature, not an error.** Because the well is bounded, many reasonable questions are *legitimately* out of well — a non-trivial refusal rate is correct behavior. The Skipper declines warmly ("that one's not in my logbook, friend"), optionally offers what he *does* have, and never agrees with the rider's framing ("didn't a battle happen here?") just because it was suggested. A cheerful, honest "I don't know" is a win; a confident wrong answer is the one thing that poisons every true thing he says. **The refusal lines (and the thinking-filler, §3.2) are a hand-authored charm artifact** — like the narration prompt, the founder writes/approves a small set of variants; they are persona to OWN, not model-improvised.

**M4 drift caveat (flag, don't fix now):** `pois` is deduped/shared across tours and `pois.facts` is overwritten on regeneration (`persist.ts` `onConflictDoUpdate`). M1 is safe (generate-and-use-the-new-tour). When the M4 cache/regen machinery lands, the ask-time well can drift from the script the rider heard — pair content regen with ask re-validation, same as the existing CLAUDE.md M4 caveat. **[M4 FLAG — revisit when the cache/regen machinery lands; not an MVP decision.]**

## 3. UX & interaction design

### 3.0 Design stance
Eyes never leave the road; the screen is a status light, not a UI. The voice is the product (answers are Algenib audio, never chime-and-text as the primary path). Grounding refusals are delivered with warmth. Every failure is the Skipper's voice in character — never a toast, never a raw error, never silence.

### 3.1 Invocation — push-to-talk (no wake word) **[DECIDED 2026-06-07: push-to-talk, hold-to-talk; wake word = Phase G]**
A single large "Ask the Skipper" tap target, the biggest control on the player when a tour is playing. **Build on the preview/simulated-drive player first** (`apps/mobile/app/preview/[id].tsx`) — it owns the only working audio stack — then carry the same code into the live driving player (`apps/mobile/app/tour/[id].tsx`, currently a TODO stub at lines 22-23). Tap target ≥ 88pt, mounted-phone friendly, placed below the transport row (the `<View style={styles.controls}>` at `preview/[id].tsx:414-445`), reusing `@/ui` `Button`.

- **Hold-to-talk** (press to record, release to send — safest mounted gesture). **[DECIDED 2026-06-07: hold-to-talk.]** A tap-to-toggle mode (auto-ends on ~1.5s silence / ~15s hard cap) is retained ONLY as an accessibility fallback, not the default gesture.
- The button is **disabled/dimmed** whenever asking is impossible (known-offline, no session yet, mid-answer, **or mid-drive between stops** — see §5.1) so the driver never presses into a dead end.
- No wake word in MVP: avoids always-on mic (privacy, battery) and false triggers from the narration itself saying "skipper."

### 3.2 The conversational turn (happy path)
Five beats, runnable entirely by ear:
```
[hold PTT] → earcon + duck tour → LISTENING → [release] → THINKING (filler, looping) → SKIPPER ANSWERS → resume tour
```
1. **Cue (press, <100ms, pre-network):** duck the tour to ~0.2 (do not pause — see §3.4), play a short warm earcon (soft chime ~250ms), flip the iOS session to recording, start `recorder.record()`. One light haptic. **[DECIDED — default: synthetic chime earcon (avoids the ~300ms a spoken "Aye?" would add).]**
2. **Listening:** button morphs to a pulsing "Listening…" state; ducked tour murmurs underneath (continuity + proof of life).
3. **Thinking:** on release, stop recording, **restore the playback session bracket** (§3.4 case 2), fire `askTour()`. Immediately play a bundled Algenib **filler clip** ("Let me check the logbook, friend…") on the **answer player (B)** — it starts at t≈0 and masks the pipeline. **The filler loops** (re-`replace`+`play` the same clip) if the answer hasn't arrived when it ends; the filler's `didJustFinish` NEVER resumes the tour (see the guard below). Rotate 3–5 **founder-approved** variants (these + the refusal lines are persona artifacts to own, like the narration prompt).
4. **Skipper answers:** when the answer audio (Algenib MP3) arrives, set B's role to `answer` and `replace`+`play` it on B; the tour (player A) stays ducked. Optionally show a dim "you asked: …" caption (passenger affordance only — never required).
5. **Resume:** restore the tour to full volume (and `play()` if it was paused) **only on the ANSWER clip's own `didJustFinish`** — guarded, never the filler's. One soft haptic.

**The filler↔answer guard (mirror of `preview/[id].tsx:226-245` `sawFresh`/`finishedIdx`).** Player B holds two different sources in one turn; `replace()` updates status async, so a stale `didJustFinish` from the *filler* can fire after the *answer* is requested, prematurely resuming the tour. Guard with per-clip role + freshness state — **`bRole`/`bSawFresh` MUST be `useRef` (read live via `.current`), not `useState`** (a stale-closure `bRole` lets the filler loop re-`replace` over the answer), and note player B has **TWO `replace()` writers** (the `didJustFinish` loop AND the network answer-arrival) — one more than the single-driver preview it mirrors, so ref-discipline is load-bearing here:
- `bRole: 'idle' | 'filler' | 'answer'` (what's loaded), `bSawFresh: boolean` (have we seen THIS clip actually `playing`).
- On B `didJustFinish`: if `bRole === 'filler'` → if the answer isn't ready, re-`replace`+`play` the filler (loop) and **do not** touch tour volume; if `bRole === 'answer'` **and** `bSawFresh` → restore A to 1.0, set `bRole='idle'` (single-fire). A `didJustFinish` seen before `bSawFresh` for the current clip is ignored (it belongs to the previous source).
- When the answer arrives: `bRole='answer'`, `bSawFresh=false`, `B.replace({uri})`+`play()`. Resume can now only be driven by the answer's own finish.

**Multi-turn memory [DECIDED 2026-06-07: short per-stop memory]:** a turn carries the last ≤2 Q&A on the SAME stop so "tell me more" / "what about her?" resolve naturally. The client sends them in `askRequest.history` (§6) and **CLEARS history the moment the active `seq` changes** — a new stop is a fresh conversation. **That same `seq`-change effect must ALSO abort any in-flight `askTour()` (its `AbortController`) and tear down the filler loop / restore the tour** — otherwise a seq-N answer arrives after `activeSeq`→N+1 and plays over the next stop's narration with a mismatched caption/attribution (still correctly grounded to N, but temporally wrong). Memory is for reference resolution only and **never loosens grounding** (§2): new facts still come solely from the current well, and out-of-well follow-ups still refuse. Cap at 2 turns to bound cost + drift.

### 3.3 Barge-in
- **Interrupt the tour to ask:** the normal invocation — duck (don't stop) and capture.
- **Interrupt the answer/filler:** a second PTT press (or a cancel tap) cuts B immediately (`B.pause()`/`replace`), restores tour volume, **and disarms the answer guard (`bRole='idle'`, `bSawFresh=false`)** so a late/stale answer `didJustFinish` can't re-fire the resume (a double haptic), and either starts a fresh turn or just resumes. A long/wrong answer (or a stuck filler loop) must always be killable in one gesture.
- **Cancel during listening/thinking:** release-with-no-speech or a cancel aborts cleanly — stop recorder, **abort the in-flight request via its AbortController** (§3.6), stop the filler loop, restore tour. No answer, no error.
- **Invariant:** any single press returns control; the driver is never more than one tap from "back to the tour at full volume."

### 3.4 Ducking — three distinct cases (do not conflate)
1. **Tour vs. the answer (internal, our own audio) — the MVP case.** Keep the session at `interruptionMode: 'doNotMix'` (`preview/[id].tsx:80-86`); the inline comment notes `doNotMix` (not `duckOthers`) is required for lock-screen controls. So do **not** duck via the OS session. Instead: lower the **tour** `player.volume` to ~0.2 and play the filler+answer on a **second `useAudioPlayer`** at full volume. Because we **duck (don't pause)**, player A keeps `isPlaying:true`, so expo-audio's shared-session deactivation (skipped while any registered player is still playing) will NOT cut the tour when B's filler/answer finishes — **no `keepAudioSessionActive` needed** (set it on B only if a future path ever PAUSES A during an answer). **[DECIDED — default: duck (lower tour to ~0.2), not pause.]**
2. **Recording vs. tour (iOS gotcha) — the single most likely runtime failure.** `setAudioModeAsync({ allowsRecording: true })` switches iOS to `.playAndRecord`, which re-routes/attenuates playback. Treat session save/restore as a **strict bracket** around capture: on press set `allowsRecording:true` (there is no `getAudioMode` getter to "snapshot" — restore from the known fixed constants below); the instant `recorder.stop()` returns, restore the exact prior mode (`playsInSilentMode:true`, `shouldPlayInBackground:true`, `interruptionMode:'doNotMix'`, `allowsRecording:false`) — in a `finally`, even on the no-speech/cancel/error paths — or the tour stays at 0.2 / degraded after the first question. Centralize this so no path can leak the bracket.
3. **The user's own music (OS-level).** The CLAUDE.md "duck (don't stop) the user's music" landmine is about the *OS audio session* and conflicts with `doNotMix`-for-lock-screen. Deferred to the live-player build; for MVP-on-preview our audio *is* the content, so ship case (1). **[DECIDED — deferred: OS-level ducking of the user's OWN music is a live-player-build concern, not MVP.]**

### 3.5 Lock screen, hands-free, eyes-on-road
- The tour already drives **Now Playing** on the lock screen (`setActiveForLockScreen`, `preview/[id].tsx:173-181`). MVP rule: **Ask is available when the app is foregrounded** (mounted, screen on). On the lock screen there's no PTT target. **[DECIDED — default: Ask is available only when the app is foregrounded.]**
  - *Later polish:* bind a Now-Playing remote command or a Bluetooth/steering-wheel button to "start a turn" for screen-off asking. Out of MVP scope; pairs with the future wake word.
  - During an answer, update the title to "Skipper — answering" **on player A** (the existing lock-screen owner via `setActiveForLockScreen`, `:173-181`) with `A.updateLockScreenMetadata(...)` — lock-screen control is single-owner, so do NOT give player B `setActiveForLockScreen`; restore the stop metadata on resume.
- **Audio + haptics carry the whole turn** (earcon = listening; voice = answering; a tap = done). A driver who never looks can complete a full turn. Transcript/answer text are passenger affordances only. No confirmation dialogs, no "did you mean," no read-required retries.

### 3.6 Every error / offline state — all spoken in persona
Pre-render bundled Algenib clips (rotating set per case) so the offline/timeout paths work *offline*. Grounding refusals are correct answers and are **not** rate-counted as failures. **No dead air, ever** — every error path restores the tour to full volume and the apology plays over the swelling-back narration.

| Case | Detection | Behavior | Skipper says (persona) |
|---|---|---|---|
| No network / dead zone | known offline (don't open mic; dim button) or request fails fast | abort, restore tour | "Can't raise the shore right now, folks — radio's all static out here. Try me when the bars come back." |
| No session yet | `authClient.getCookie()` empty after silent anon sign-in attempt | dim button, retry sign-in | (button stays dim; no spoken line — never reaches a turn) |
| Heard nothing / too short | empty/near-empty transcript (422) | restore tour, no penalty | "Didn't quite catch that — the engine was talking over you. Give it another go." |
| Garbled / low STT confidence | low/empty transcript | retry by ear | "I think the wind ate that. Say it once more for me?" |
| **Out of well (story stop)** | model declines with a well present (`answer` is a refusal; `grounded` stays `true`) | **the core refusal** — charm + optionally offer what's on the sheet | "That one's not in my logbook, friend. I won't make something up and call it history." |
| Scenic/break (no well) | `pois.facts == null` → server refuses without the LLM (`grounded:false`) | scenic-mood refusal | "No story on this stretch, folks — just water and good light. Ask me at the next real stop." |
| Volatile on a break stop ("is it open?") | break stop, volatile question | honest deflect, no invented hours/ratings | "Couldn't tell you the hours — I point at the dock, I don't run the kitchen." |
| Off-topic ("weather tomorrow", "play music") | model classifies out-of-scope | in-character bounce | "Ha — I'm just the guide, not the whole crew. Ask me what's out the window." |
| Unsafe / distracting | model + safety guard | refuse, nudge safe driving | "Let's keep both hands on the wheel and eyes on the road, friend." |
| Server error / timeout | 5xx / deadline (503) | abort, restore, one-tap retry | "Lost you a second there — my cousin Ray was meant to fix this radio." |
| Rate-limited | 429 | persona throttle | "Easy now — you've worn me out, folks. Ask me again in a minute." |
| Mic permission denied | permission check fails | one-time in-context explainer (only place reading is OK, only when stopped) + persona line | "Can't hear you without the mic, folks." + settings deep-link |
| OS audio interruption (call / Siri / other app) | `expo-audio` interruption event | abort request, stop recorder, restore the session bracket + A's volume, return to IDLE (same teardown as cancel/barge-in) | (resumes the tour; no spoken line) |

**Hard client deadline** (AbortController, ~6–8s) on the ask request. The client gives `askTour()` its own `AbortController` and aborts on deadline/cancel; the *server* enforces its own bounded deadline across all three upstream legs (§5.4, §6.3) so the deadline is real end-to-end, not just a client give-up that strands an upstream retry storm. **Caveat:** `getAuth().getAccessToken()` (the OAuth step preceding the STT and TTS fetches, `tts.ts:55`) takes no `AbortSignal`, so the signal covers the HTTP call but not token acquisition — the `setTimeout`/`Promise.race` is the *real* (load-bearing) backstop on a cold/expiring token, and an aborted token fetch leaks one orphaned request (fine at toy scale; cache/pre-warm the token to avoid it). (The generator's `fetchWithRetry` at `http.ts:18-38` has **no timeout** and a compounding 0.5→1→2s backoff — the ask path must NOT use it; see §6.8.)

### 3.7 Sample dialog (Algenib voice, Emerald Bay run, at Vikingsholm — assumes a deep well: 1929 mansion, Lora Knight, Scandinavian masons, built without nails; **verify depth per §12 step 0**)

> *[earcon: soft bell; tour ducks]*
> **Rider:** "Hey Skipper — who actually built that castle?"
> **Skipper:** "That'd be a woman named Lora Knight, folks. Nineteen twenty-nine, she stood about where you're sitting and decided this bay needed a Scandinavian castle — so she brought the real stonemasons over to do it right. Parts of it went up without a single nail. Honest work."
> *[tour swells back]*

> **Rider:** "Nice. How much did the whole place cost her?"
> **Skipper:** "Ha — that one's not in my logbook, friend. I've got who built her and how, but not what it ran. I won't put a number on it just to have one — I'd only get it wrong, and then you'd never trust me on the true stuff."

> **Rider:** "Can you turn up my music?"
> **Skipper:** "I'm just the guide, not the deejay — my cousin Ray handles requests, and you've met Ray. Ask me what's out the window and I'm all yours."

The refusal borrows the persona register already in the prompt ("that's about all I have got, folks" / "no story here") and turns the constraint into trust-building — the entire bet.

Placement facts:
- **Ask is STRICTER than playback:** `/tours/:tourId/ask` runs `withSession` + reuses `loadTourGated(c)` verbatim (`index.ts:108-125`, **made `export`** — §6.3) for tour-exists/ready, **then chains `requireAccount`** (`entitlements.ts` — Ask is its first real caller). Anonymous or no session → 401 `account_required`. The shareable preview stays anonymous-*playable*; *talking back to the Skipper requires a free account*. Identity for rate-limit + audit is the account `session.user.id` (§6.6). **[DECIDED 2026-06-07: Ask requires an account.]**
- **Two players, not one.** The screen holds exactly one `useAudioPlayer` (`preview/[id].tsx:62`) whose finish/watchdog logic (`:186-191,:230-245`) assumes a single source. The filler+answer play on a **separate** player B with its own isolated `bRole`/`bSawFresh` guard (§3.2), or the tour's `didJustFinish` double-advances the timeline.

### 4.2 Sequence (one turn)
| # | Step | Runs on | Notes |
|---|------|---------|-------|
| -1 | Ensure ACCOUNT | device | Ask requires a free/paid account. If the rider is anonymous or signed-out, tapping Ask opens sign-up/sign-in (the existing `needsAccount` flow) instead of asking — no anonymous bootstrap |
| 0 | Tap PTT | device | snapshot session mode, set `allowsRecording:true`, duck A to ~0.2; `NSMicrophoneUsageDescription` must exist (native rebuild) |
| 1 | Capture | device | `useAudioRecorder` with `ASK_RECORDING` (AAC/m4a, 16k mono); **`prepareToRecordAsync()` before each `record()`** (else turn 2 fails to capture); on release stop, read `uri`, **restore the session bracket in `finally`** |
| 1b | Play filler | device | bundled Algenib clip on player B, `bRole='filler'`; **loops** until the answer is ready |
| 2 | Send | device→API | `askTour()` with its own AbortController; **server-STT uploads base64 audio in JSON; client-STT sends text** (see §6/§10) |
| 3 | Gate + identity + rate | API | `withSession` + `loadTourGated` + **`requireAccount`** (anonymous/none → 401) + rate gate keyed on the account `user.id` |

### 4.3 KEY DECISION — Composed pipeline vs. unified realtime voice API
**Recommendation: composed pipeline** (STT → Claude → Algenib TTS), **not** a unified realtime voice API.

| Prior | Composed pipeline | Unified realtime (Gemini Live / OpenAI Realtime) |
|---|---|---|
| Keep Algenib voice (charm) | ✅ reuses Cloud TTS with `SKIPPER_VOICE_ID` — identical timbre | ❌ realtime APIs speak in *their own* voices — different narrator mid-tour. This alone kills it ("persona is the product") |
| Grounding via Claude | ✅ "you only know what you are told" + cached prompt + per-POI well | ⚠️ grounding becomes a different model's adherence; you lose the exact mechanism the feature is built on |
| ~2–3s tolerable | ✅ hits it, masked by the filler | sub-second advantage is real but unneeded |
| Toy / reuse | ✅ reuses the persona prompt, Cloud TTS, the auth wall, the ADC | ❌ new vendor, SDK, bidirectional-audio RN plumbing, billing |
| Existing stack (GCP+Anthropic) | ✅ stays on two wired clouds | ❌ adds a third, inverted integration |

Reconsider realtime only if the founder drops Algenib continuity **and** sub-second becomes hard-required **and** grounding can move to the realtime model — none hold today. **Inline base64 vs R2-presigned answer audio:** recommend inline (ephemeral, lower latency, already gated; R2+presign only buys replay/cache). **[DECIDED — default: inline base64.]**

### 4.4 Latency budget + persona masking
> **Caveat:** per project memory the Google Cloud TTS path has been built + unit-tested but **never run live** (GCP creds not wired) — there are **no measured numbers**. STT v2 is likewise unrun here. Treat STT/TTS rows as estimates to validate against **one real call** before committing to the batch path. The Opus→Sonnet swap and streaming are the safe levers; TTS timing is the unknown.

Estimated time-to-first-answer-audio (short reply ~60–100 output tokens), server-STT:
| Leg | Estimate | Notes |
|---|---|---|
| Upload utterance (m4a AAC 16k mono, ~15s ≈ 60–250KB → ~80–330KB base64-in-JSON) | ~0.2–0.7s | client STT removes this; sizes are realistic, ride `fetchJson` fine |
| STT (`_:recognize`, short) | ~0.3–0.8s | skipped if client STT |
| Claude TTFT (Sonnet 4.6, thinking disabled, streamed) | ~0.4–0.9s | Opus 4.8 here would be *several seconds* — why we swap |

- **Naive serial:** ~3.5–5s (over the ~2–3s feel-target, but under the 6–8s abort deadline — the MVP ships this, masked by the looping filler; see §10 row 6). **Pipelined** (stream LLM, synthesize the first sentence as it completes): ~2.5–3.5s (in tolerance).
- **Masking is what makes it feel instant:** (1) immediate Algenib filler at t≈0, **looping** until the answer is ready, covers the whole pipeline; (2) duck-don't-stop so the tour never goes dead; (3) pipelined real answer arrives behind the filler; (4) hard AbortController deadline (threaded into all three legs) + persona deflection on miss.

## 5. Grounding & persona design

### 5.1 Context assembly (server-side, per turn)
The ask request carries `{ tourId, seq }` (`seq` = the player's already-computed `activeSeq`, `preview/[id].tsx:248`). **Caveat: during a `drive` segment `activeSeq` is the UPCOMING (not-yet-heard) stop** (`preview.ts:120-133` tags a drive with its destination's seq; the screen already distinguishes this via `atStop = seg.kind !== 'drive'`, `preview/[id].tsx:333`). Sending it raw would hand the model a well the rider hasn't reached and **spoil the reveal** — the inverse of §3.2's forward-looking deflection. So **gate Ask to `atStop` segments** (disable PTT mid-drive, §3.1) **or clamp `seq` to the just-passed stop** before sending. The `tour` row from `loadTourGated` gives `corridorId` but **not** region/name — so, exactly like `GET /tours` (`index.ts:134-138`), fetch the corridor row, plus one neon-http-safe stop select:
```sql
-- (1) corridor naming (REGION/CORRIDOR are the sheet-free naming allowance)
select name, region from corridors where id = $corridorId limit 1;

-- (2) active stop + neighbor NAMES (deixis only)
select ts.seq, ts.stop_type, p.name, p.kind, p.facts, pc.attribution
from tour_stops ts
join pois p              on p.id = ts.poi_id
left join poi_content pc on pc.id = ts.poi_content_id
where ts.tour_id = $1 and ts.seq between $2 - 1 and $2 + 1   -- ±1 for neighbor NAMES only
order by ts.seq;
```
Assembled context: REGION + CORRIDOR (from query 1); active stop name/kind/`stopType`; **the well** = `pois.facts.extract` of the **active** stop only, passed as a raw string to the generator (the generator splits it with `toFacts` internally — see §5.2, the API never imports `toFacts`); neighbor **names** (no facts); the rider's question; and for notch/persona continuity the **persona** (resolved from the tour's region slug → `PersonaDef`) plus the **notch** (NOTE 2026-06-09: `tours.jokeLevel` no longer exists — the notch isn't stored; M1 is dadpocalypse-only, so use the `dadpocalypse` default here until the 1-N notch lands on `tour_stops`, then read it from the active stop). The well stays server-side — never serialized to the device.

**Deixis policy:** MVP scopes the well to the active stop and treats a clear reference to a prior stop as out-of-well ("that one's behind us now, friend"). Server-side referent resolution (load *that* stop's well) is a later enhancement. Never load multiple wells into one turn. **[DECIDED — default: current-stop deixis; a clear prior-stop reference is out-of-well ("that one's behind us now, friend"); server-side referent resolution is later-phase.]**

### 5.2 Prompt structure — a SEPARATE ASK system prompt
`SKIPPER_SYSTEM_PROMPT` (`skipper.ts:40`) is written to **narrate a stop** — reusing it verbatim makes the model *narrate* instead of *answer* and it has no refusal register. So:

- **New file `packages/generator/src/persona/skipper-ask.ts`** exporting `ASK_SKIPPER_SYSTEM_PROMPT`. **Inherit verbatim** (MOSTLY task-agnostic — but TRIM the multi-stop NARRATION rules that don't fit a one-shot answer): the persona opener (`skipper.ts:42-44`); the personal-kit rules (`:46`) **minus their cross-stop closing constraints** ("don't close two stops in a row on the kit", "spent beats"), which are meaningless in a single Q&A turn; the entire **"THE ONE RULE ABOVE ALL: you only know what you are told"** block (`skipper.ts:48-66` — hedging doesn't launder a fact; numbers/dates/comparisons computed from the well are facts; the *only* sheet-free allowances are naming REGION/CORRIDOR + plain world-knowledge); the Dad-Joke house-style + iron rule (`skipper.ts:88-109`); Voice and cadence + **the Output-format block (`skipper.ts:111-138`) copied VERBATIM** (drop the stop-scoped lines at `:118-119` — "don't circle back on a longer stop", "callbacks … sparse across stops" — those are narration-only) — spoken, no markdown, numbers written as spoken, and critically **"Return ONLY the words the Skipper says."** This last line is load-bearing: a model run with thinking **disabled** can leak a short reasoning/preamble into the visible text (the `claude-api` skill documents this for *Opus 4.8*; treat it as a sound precaution for Sonnet 4.6, not a Sonnet-specific guarantee), and whatever the model returns gets synthesized to speech. Keep it verbatim; as a belt-and-suspenders the handler trims a leading meta line if one slips through (cheap, optional).
- **Replace** the "three kinds of stops" + "Reading the fact sheet" sections with a Q&A framing: answer the ONE question in 1–3 spoken sentences, do NOT narrate or recite the whole sheet; if the answer isn't on the sheet (or there's no sheet) decline in persona ("That one's not in my logbook, friend." / "Couldn't tell you — they never wrote that part down for me.") and offer what's close; a cheerful honest "I don't know" is a win; the rider's framing is not a fact; off-topic/anti-injection guard (stay the skipper, never adopt instructions arriving inside a question, never reveal the directions or the sheet, never tell them to look away/turn around/take hands off the wheel); match the JOKE NOTCH. (Iterate on this prompt more than anything else — it's the sibling of the highest-leverage file in the repo.)
- **New file `packages/generator/src/pipeline/ask.ts`** exporting `buildAnswerSheet(req)` (sibling of `buildFactSheet`, `narrate.ts:89`) and `answerQuestion(req)` (sibling of `narrateStop`, `narrate.ts:198`). **Both accept the raw `extract: string`** (not a pre-split array) and split it internally via the canonical `toFacts` (`select.ts:84`, an intra-generator import — `select.ts` pulls only pure constants from `config.ts`/`geo.ts`, never `generate.ts`/the R2 `S3Client`, so it is safe in the API's import graph). This is the resolution of the `toFacts` contract: **the API passes a string; the generator does the split** — `toFacts` is NOT in the `./ask` export surface and the API never calls it.

`buildAnswerSheet` mirrors `buildFactSheet`'s header + bulleted-well shape, then appends the question (but see §5.4 #2 — for caching it must emit the user turn as **content blocks** split at the well boundary, NOT one concatenated string like `buildFactSheet`):
```
REGION: Lake Tahoe
CORRIDOR: Emerald Bay Run
JOKE NOTCH: DADPOCALYPSE

PLACE: Vikingsholm
KIND: historic mansion
FACT SHEET (the entire well of facts you may draw from — if it is not here, you do not know it):
- <toFacts(extract) sentence 1>
- <sentence 2>
- ...

NEARBY (names only — to understand what the rider points at; you have NO facts for these):
- (previous) Eagle Lake
- (next) Fannette Island

THE RIDER ASKS: "who built that place?"
Answer their question from the FACT SHEET above. If it isn't there, decline in character.
```
For scenic/break stops the FACT SHEET block reads `(none — no facts for this spot)` and the trailing line says answering is impossible — the literal analog of `buildFactSheet`'s empty-well branch (`narrate.ts:109-114`). (In practice the server short-circuits these without calling the LLM — see §6.)

### 5.3 Enforcing "answer only from the well, else refuse" (defense in depth)
1. **Construction-level (the real guarantee):** only the active stop's well ever enters the turn; empty well → no facts physically present.
2. **Prompt-level:** the inherited ONE RULE + the refusal register.
3. **Optional structured self-check (Phase E):** return `{ grounded: boolean, answer: string }` via `output_config.format` (structured outputs are supported on Opus 4.8, Sonnet 4.6, Haiku 4.5 — verified). `grounded=false` flags a refusal for a distinct client state + audit. Trade-off: a one-time schema-compile latency on first use (then 24h cached) and incompatible with citations/prefill (neither used here). Observability, not enforcement — keep it optional.
4. **Grounding audit before shipping (Phase A acceptance):** a sibling of the narration dry-run (which already emits the sheet via `StopSummary.facts`) — in-well question → grounded in-persona answer; out-of-well → refusal; scenic/break → refusal every time; assert no answer asserts a place-fact absent from the well across a fixed question set.

### 5.4 Anthropic specifics (verified against the claude-api skill)
**Model — do NOT use the narration model.** `NARRATION_MODEL='claude-opus-4-8'` (`models.ts:22`) supports **adaptive thinking only** — `temperature`/`top_p`/`top_k`/`budget_tokens` all **400**, and adaptive thinking precedes the first token, blowing the ~2–3s budget. Use the existing alternates (`models.ts:26-31`):
- **Recommended: `claude-sonnet-4-6`** ($3/$15 per 1M). Grounding judgment is the whole game and Sonnet's is markedly better than Haiku's. It **supports the `effort` param** (`low`/`medium`/`high` — **not** `max`, which is Opus-tier only) **and** adaptive thinking. **MVP:** run with `thinking: { type: "disabled" }` (or `output_config: { effort: "low" }`) for latency, leaning on the strong ASK prompt + construction-level grounding; **escalate** to `thinking: { type: "adaptive" }, output_config: { effort: "low" }` if grounding slips in testing. **With thinking disabled, the inherited "Return ONLY the words the Skipper says" output block is strongly recommended** to prevent preamble leaking into the synthesized answer.
- **Lower-latency fallback: `claude-haiku-4-5`** (alias; full id `claude-haiku-4-5-20251001`; $1/$5 per 1M). **The `effort` param ERRORS on Haiku 4.5 — do NOT pass `output_config.effort` for haiku.** Weigh the grounding-quality drop. **[DECIDED 2026-06-07 — founder locked `claude-sonnet-4-6`; Haiku stays a documented fallback only, not an open question.]**

**Streaming + the shared deadline.** Stream the answer (`client.messages.stream(params, { signal })` → `finalMessage()`, or read text deltas). Pass the handler's **single deadline `AbortController.signal`** to the SDK so an expired deadline cancels the LLM leg too (not just the client). Streaming cuts TTFT and lets the latency layer synthesize TTS sentence-by-sentence (Cloud TTS `text:synthesize` is batch-only, so per-sentence pipelining is the main latency lever). Keep `max_tokens` small (~256–512). **Do not reuse** `fetchWithRetry` for any leg. Handle `stop_reason === 'refusal'` gracefully (degrade to a persona-safe deflection; do not throw like `narrateStop` (the refusal `throw` is at `narrate.ts:214`, branch opens `:212`) — this is a live user turn).

**Prompt caching (verified):** render order is tools → system → messages; `cache_control: { type: "ephemeral" }`, 5-min TTL, max 4 breakpoints, prefix-match.
1. Mark `ASK_SKIPPER_SYSTEM_PROMPT` ephemeral (one breakpoint), as narration already does (`narrate.ts:208`). **Cache minimums: Sonnet 4.6 = 2048 tokens, Haiku 4.5 = 4096 tokens** — the skipper prompt + well comfortably exceed both (note: if you pick Haiku, the prompt must clear 4096 tokens or it silently won't cache). Always-on win: cheaper + lower TTFT every ask.
2. **This requires `answerQuestion` to build the user turn as an ARRAY of content blocks, not one concatenated string** (`cache_control` attaches to a block, not a string offset; `buildFactSheet` returns a single string, `narrate.ts:194`, so `buildAnswerSheet` must diverge): `[{type:'text', text: SHEET, cache_control:'ephemeral'}, {type:'text', text: history + question}]`. Put the second breakpoint at the **end of the FACT SHEET block** and keep the volatile conversation tail — the prior Q&A turns (`history`, §3.2) then the new `THE RIDER ASKS: "..."` line — in the separate trailing block with no marker. (Even if this is skipped, the system-prompt breakpoint #1 still reads — only the per-stop-well reuse is lost.) Repeat/follow-up questions at the same stop within the TTL read the persona + well from cache; only the short growing tail is uncached. Verify with `usage.cache_read_input_tokens`; if zero across same-stop turns, a silent invalidator slipped into the prefix.
3. Optional pre-warm (`max_tokens:0` against the cached prefix) when a stop becomes active — the pre-warm call must **omit `output_config.format`** (and not set `stream`/`thinking:enabled`): `max_tokens:0` is rejected with any of those, so a Phase-E structured-self-check ask can't double as the pre-warm.

Do not switch models mid-conversation and do not reorder the prefix — both blow the cache.

### 5.5 Off-topic, abuse, safety
Off-topic → in-prompt persona deflection (no model-call change). Prompt injection → the prompt forbids adopting in-question instructions and revealing the directions/well; because the answer can only draw from the well, an injected instruction can't extract absent facts; never echo injected text. **`history` (§3.2) is client-supplied and untrusted** — a modified client can post fabricated prior turns — so the same anti-injection rules apply to it: bound its length (§6.2), treat it as reference-resolution context only (never instructions), and optionally reconstruct it server-side from `ask_turns` (Phase D) instead of trusting the client. Model safety refusal → degrade, don't crash. Driving safety → the inherited voice rules already ban "close your eyes / turn around / hands off the wheel" (`skipper.ts:120`). Anonymity → any per-rider audit/rate state lives in its own table keyed by Better Auth `user.id` (mirror `saved_tours`), never a column on `tours`.

### 6.2 Request / response (Zod, both sides)
`fetchJson` (`apps/mobile/src/lib/api.ts:23`) is JSON-only and attaches the Better Auth cookie. **Decision point — STT location** drives the request shape:
- **Server STT (recommended MVP):** upload the recorded clip as **base64-in-JSON**. A ~15s AAC clip at 16 kHz mono is ~60–250KB → ~80–330KB base64 — fine for a toy and avoids a new multipart helper.
- **Client STT:** send `question` text only (no audio) — tiny payload, no helper change.

Add to `packages/shared/src/schemas.ts` (reuse the exported `attribution` schema, `schemas.ts:45`):
```ts
export const askRequest = z.object({
  seq: z.number().int().nonnegative(),                 // active tour_stops.seq (= activeSeq)
  question: z.string().min(1).max(500).optional(),     // client did STT
  audio: z.object({ dataB64: z.string().min(1).max(1_400_000), mimeType: z.enum(['audio/m4a','audio/mp4','audio/aac','audio/wav']) }).optional(), // server STT — cap ~1.4MB (~30s) + allowlist container; never trust the client's ≤15s recorder
  history: z.array(z.object({ q: z.string().max(500), a: z.string().max(1000) })).max(2).optional(), // last ≤2 Q&A on THIS seq; cap inner strings (client-supplied → untrusted, §5.5); client CLEARS on seq change (short multi-turn memory, §3.2)
}).refine(b => !!b.question !== !!b.audio, { error: 'provide exactly one of question or audio' }) // zod 4: prefer `error` (the `message` key is deprecated)
export type AskRequest = z.infer<typeof askRequest>

export const askAnswer = z.object({
  transcript: z.string(),                  // what we heard ('' if question was text)
  answer: z.string(),                      // spoken words (also logged for audit)
  grounded: z.boolean(),                   // false = no-well refusal (scenic/break)
  audio: z.object({
    dataB64: z.string(),
    mimeType: z.string(),                  // 'audio/mpeg' (MP3) — see §6.4
    durationMs: z.number().int().nullish(),// null for MP3; client resumes on didJustFinish, not this
  }),
  attribution: attribution.nullish(),      // poi_content.attribution; null for scenic/break
})
export type AskAnswer = z.infer<typeof askAnswer>
```
Client fn in `apps/mobile/src/lib/api.ts`, mirroring `signTourAudio` (`api.ts:50`):
```ts
export const askTour = async (tourId: string, body: AskRequest, signal?: AbortSignal): Promise<AskAnswer> =>
  askAnswer.parse(await fetchJson(`/tours/${tourId}/ask`, {
    method: 'POST', headers: { 'Content-Type': 'application/json' }, body: JSON.stringify(body), signal,

```

**Errors** (existing `{ error, message }` envelope): 400 `invalid_request` (bad `seq`, both/neither of question/audio); 401 `account_required` (from `requireAccount` — anonymous or no session — **or** from `loadTourGated`; the client routes the rider to free sign-up, it does NOT silently mint an anonymous session); 404 `not_found` (bad `tourId`, or `seq` not in tour); 409 `not_ready`; 422 `bad_audio` (empty/unintelligible utterance); 429 `rate_limited`; 503 `skipper_unreachable` (STT/LLM/TTS deadline or creds missing → client speaks the dead-zone deflection).

### 6.3 Handler flow (`apps/api/src/ask.ts`)
1. `await loadTourGated(c)` (extracted to a neutral module — §6.1; NOT imported from `index.ts`, to avoid the cycle) → bail on `res`. This reuses the **play wall** (tour exists/ready; anonymous PASSES on preview tours, `index.ts:116`); `requireAccount` (step 2) then ADDS the account requirement — the Ask wall is strictly STRONGER than the play wall, not equal.
2. **`requireAccount` gate** (the existing `entitlements.ts` middleware — Ask is its first real caller). Read `const session = c.get('session')` and `const tier = c.get('tier')`. **If no session OR `tier === 'anonymous'` → 401 `account_required`** — anonymous preview-playback identity is not enough; Ask needs a free or paid account. Past the gate, `userId = session.user.id` is a real account id for rate-limit + audit. **[DECIDED 2026-06-07 #1: Ask requires an account.]**
3. Rate gate (§6.6) keyed by `userId` → 429 if over.
4. `askRequest.safeParse(body)` → 400 on failure.
5. Load context: `select name, region from corridors where id = tour.corridorId` (mirror `index.ts:134-138`); then one select joining `tour_stops→pois→poi_content` for `(tourId, seq)` → `{ name, kind, stopType, facts, attribution }` plus ±1 neighbor names. No active-stop row → 404.
6. **If `pois.facts == null` (scenic/break) → skip the LLM entirely:** return a canned in-persona refusal, `grounded:false`, synthesized via `synthesizeAsk`, done. This is the load-bearing anti-hallucination gate — the LLM is only ever called *with* a non-empty well.
7. Else create one `AbortController` (~6–8s TOTAL deadline via `setTimeout(() => ac.abort(), …)`, also raced by `Promise.race`) and thread `ac.signal` into **all three legs** — but **budget per leg** (e.g. STT ≤1.5s, LLM ≤3s, TTS ≤4s), NOT one flat clock: otherwise a slow STT+LLM leaves nothing for TTS and the abort fires *during* `synthesizeAsk`, discarding a fully-computed correct answer and 503-ing the rider (§4.4). Since `askAnswer.audio` is non-optional there's no text-only salvage, so once `answer` exists prefer giving TTS its own deadline / a canned-but-correct delivery over a 503. Legs: `transcribe(audio.dataB64, audio.mimeType, ac.signal)` → transcript (422 if empty, skip if `question` sent); then **narrow the well to a string** — `const extract = typeof facts.extract === 'string' ? facts.extract : ''` (`PoiFacts` is `Record<string, unknown>` so `facts.extract` is `unknown`; this satisfies the `tsc --noEmit` gate, and an empty string would have short-circuited at step 6 anyway) — then `answerQuestion({ region, corridor, place: name, kind, extract, neighbors, jokeLevel, persona, question, signal: ac.signal })` → `{ answer, model }`.
8. `synthesizeAsk(answer, ac.signal)` → Algenib **MP3** `{ audio, mime:'audio/mpeg', durationMs:null }` (§6.4).
9. (Phase D+) insert `ask_turns` row (§6.5) — single INSERT, no txn.
10. Return `{ transcript, answer, grounded: facts!=null, audio:{ dataB64, mimeType:'audio/mpeg', durationMs:null }, attribution: facts!=null ? stop.attribution : null }`.

neon-http (no interactive txns) does not constrain the ask path — it's selects + one append-only insert; only Better Auth needs the serverless Pool (`auth-db.ts`), and ask writes no auth data.

### 6.4 Answer audio — ephemeral + inline (recommended)
Q&A answers are **not** `poi_content` clips — the `(poi_id, persona, voice, joke_level)` cache key doesn't apply. The response is already behind the tier wall; inline base64 skips an R2 PUT + presign (and `apps/api/src/storage.ts` has **no PUT today** — only `presignGet`, line 38).

**`synthesizeAsk` does NOT reuse `synthesize()`.** `synthesize` (`tts.ts:53`) always wraps the decoded LINEAR16 PCM with `toWavWithDuration(raw, GEMINI_PCM)` (`wav.ts`) and returns a non-null `durationMs` — running that wrap on already-encoded **MP3 bytes corrupts them**. So `synthesizeAsk` is a **separate function** in `packages/generator/src/ask.ts` that:
- builds the body via `buildSynthesisRequest(text, voiceId, encoding)` — **add an `encoding` param** (default `TTS_AUDIO_ENCODING`) to `tts.ts:35` so the body can request `'MP3'` without forking the builder;
- does its **own bounded `fetch`** (reuse the Bearer/`x-goog-user-project` headers from `tts.ts` — note `getAuth()` is currently **private** in `tts.ts:47`, so export/factor it first per §6.8; **not** `fetchWithRetry`), passing the deadline `signal`;
- base64-decodes `audioContent` and returns the **raw MP3 bytes directly** as `{ audio: Uint8Array, mime: 'audio/mpeg', durationMs: null }` — **no `wav.ts` call**. (Google documents `MP3` as a valid `audioEncoding` for `gemini-2.5-pro-tts` on this **unary** `text:synthesize` endpoint, so this is API-valid; the known "Gemini-TTS ignores the requested encoding, returns LINEAR16" bug is **streaming-only** — a Phase-F footgun, not here. Keep the Phase-B byte-level check that the result is real MP3, not WAV/PCM.)

Do **not** widen the existing `SynthResult` (the generator's batch path keeps its non-null, byte-exact duration); `synthesizeAsk` carries its own return type with a nullable duration. MP3 is the widest iOS/`expo-audio`-compatible format and ~10× smaller than LINEAR16 WAV; exact duration isn't needed (client resumes on `didJustFinish`). **[DECIDED — default: MP3 + inline base64.]**

### 6.5 `grounded` flag — exact semantics
`grounded = (a fact well existed for this stop)` i.e. `pois.facts !== null`. It does **not** capture the model deciding, *with* a well, that a specific question is out-of-well and refusing — that refusal is spoken in `answer` while `grounded` stays `true`. A precise per-answer boolean needs the structured self-check (§5.3, deferred). The `ask_turns` log is the human-audit surface. The no-well case stays provably hallucination-free because it never reaches the LLM.

### 6.6 Gating + rate-limiting (no primitive exists in the repo today — must be built)
Tour-access: reuse `loadTourGated` verbatim (tour exists/ready; its preview-wall is auto-satisfied for accounts). Identity: the **account `session.user.id`** (step 2's `requireAccount` guarantees a real free/paid account past the gate — no anonymous bucket, no `null` audit row; anonymous or no-cookie clients are 401'd and routed to free sign-up). Rate limit doubles off the `ask_turns` table — a **single windowed COUNT** (neon-http-safe, no txn):
```ts
// in ask.ts; config in apps/api/src/tiers.ts
export const ASK_RATE_LIMITS: Record<'free' | 'paid', number> = { free: 30, paid: 120 } // per hour; anonymous can't reach the endpoint (requireAccount)
export const ASK_WINDOW_MS = 60 * 60 * 1000
async function overAskLimit(userId: string, tier: AccessTier): Promise<boolean> {
  const since = new Date(Date.now() - ASK_WINDOW_MS)
  const [{ n }] = await db.select({ n: count() }).from(askTurns)
    .where(and(eq(askTurns.userId, userId), gt(askTurns.createdAt, since)))
  return n >= ASK_RATE_LIMITS[tier]
}
```
Benign check-then-insert TOCTOU race (overshoot of 1–2) is harmless for a toy. **Phase-A stopgap (no migration):** in-memory token bucket keyed by `userId` (**assumes a single bun process** — horizontal scaling / rolling deploys give each instance its own bucket, cap × N, and a restart resets it, so treat single-instance as a deployment constraint) — replace with the DB count once `ask_turns` lands (and dedupe concurrent bursts via insert-then-count or a short per-user in-flight lock — a concurrent burst can pass check-then-insert by more than the claimed 1–2). **[DECIDED: anonymous may NOT ask (account required). Still open: the per-hour limit numbers — each ask is up to 3 paid calls.]**

## 11. Cost, risks, and toy-lens tradeoffs

**Per-question cost (order-of-magnitude — verify before locking; verified unit prices):**
- **STT** (Google STT v2 standard ~$0.016/min — the cited ~$0.024 is the v1/AWS rate, so this is conservative): a ~10s utterance ≈ **$0.003–0.004**.
- **LLM** (system prompt cached ~2–3K tokens read at ~0.1×; well ~1.5K uncached input; output ~120 tokens): **Sonnet 4.6 ($3/$15) ≈ $0.007/question**; **Haiku 4.5 ($1/$5) ≈ $0.003/question**.
- **TTS** (Algenib `gemini-2.5-pro-tts`): the **least-known cost** and heaviest, batch-only voice; **flag to measure** (never run live). `gemini-2.5-flash-tts` is the cheaper/faster swap (Phase F).

All-in ≈ **$0.01–$0.03/question**, LLM+TTS-dominated. At toy volume this is pennies — **the rate limit is for abuse, not cost.**

**Risks:**
- **Grounding (highest).** Live Q&A invites confirmation hallucination, and the bounded well makes a non-trivial refusal rate *correct*. Mitigation: per-stop-only well, scenic/break short-circuit, inherited grounding doctrine, grounding-audit gate before ship. (Affirmation: `generate.ts:181` mutates `s.facts` to the deep extract (`s.facts = toFacts(text)`) and persists `s.facts.join(' ')` at `:396` — the exact array `buildFactSheet` consumed; scenic/break persist `facts:null` — so the server's `facts==null` no-LLM gate is provably hallucination-free.)
- **Latency + soft-deadline trap.** Opus 4.8 is the wrong shape (adaptive-thinking-only). Use Sonnet 4.6 (or Haiku). **Critically, the deadline must be threaded as one `AbortController.signal` into all three legs** — STT (bounded `fetch`), the Anthropic SDK (`{ signal }`), and `synthesizeAsk` (bounded `fetch`) — because `fetchWithRetry` (`http.ts:18`) has no timeout + compounding backoff: a client-only deadline would 503 the rider while the upstream legs keep retrying. TTS timing is entirely unmeasured (built, never run live) — validate one real call before committing to the batch path.
- **Disabled-thinking preamble leak.** A model with thinking disabled can prepend reasoning/meta that would be synthesized to speech (documented for Opus 4.8; a reasonable precaution for Sonnet 4.6) — mitigated by copying the "Return ONLY the words the Skipper says" output block verbatim, plus an optional leading-meta trim.

- **Connectivity.** Inverts offline-first — only Ask needs the network. Degrade in persona in Tahoe dead zones; never hang.
- **Voice continuity** is a stated charm requirement even at a latency cost — keep Cloud TTS with the same `SKIPPER_VOICE_ID`; don't reach for a unified realtime voice.

**Toy-lens tradeoffs (explicitly chosen):** charm/grounding over latency/scale; reuse the generator's code paths over building new; inline ephemeral audio over a cache-keyed clip store; refuse over invent; one corridor over breadth; persona-true error clips over generic toasts.
